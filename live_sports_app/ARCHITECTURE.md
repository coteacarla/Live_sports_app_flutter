# Live Sports App — Architecture & Code Documentation

## Overview

A Flutter app that shows live sports scores, upcoming fixtures, and past results across Football, Basketball, Volleyball, and Hockey. Data comes from two public APIs: **ESPN** (scores, live data, commentary) and **TheSportsDB** (sport/league metadata). State is managed with **Riverpod 3** (code-gen style).

---

## Tech Stack

| Concern | Package |
|---|---|
| State management | `flutter_riverpod` + `riverpod_annotation` (code-gen) |
| HTTP | `dio` via a thin `DioClient` wrapper |
| Local storage | `hive_flutter` (notification preferences) |
| Local notifications | `flutter_local_notifications` |
| Push notifications | `firebase_messaging` (wired, not yet handled beyond logging) |
| Immutable models | `freezed` + `json_serializable` (generated) |
| Value equality | `equatable` |

## App Entry & Navigation

**`main.dart`** boots three things before `runApp`:
1. Hive (local storage for notification preferences)
2. `LocalNotificationService` (requests OS permissions)
3. Firebase (FCM background handler registered; foreground messages only logged)

**`app.dart`** renders a `MaterialApp` with `_RootShell`, a three-tab `NavigationBar`:

| Index | Tab | Screen |
|---|---|---|
| 0 | Sports | `SportsScreen` |
| 1 | Live | `LiveMatchesScreen` |
| 2 | Results | `ResultsScreen` |

Tabs are kept alive with `IndexedStack`. Tapping a match card on Live or Results pushes `MatchDetailScreen` via `Navigator.push`.

## Data Flow

```
UI widget
  └─ ref.watch(someProvider)
       └─ Notifier (_fetchX)
            └─ UseCase
                 └─ RepositoryImpl
                      └─ RemoteDataSource  →  ESPN / TheSportsDB HTTP
```

All repository methods return `Result<T, Failure>` (a sealed type with `ResultSuccess` and `ResultFailure`). The notifier calls `.fold()` on the result to separate success from error without exceptions leaking into the UI layer.

## Providers

All providers live in `features/matches/providers.dart` and `features/sports/providers.dart`. Infrastructure providers (Dio, connectivity, notifications) are in `injection/providers.dart`.

### Global state (keepAlive: true — survive tab switches)

| Provider | Type | Purpose |
|---|---|---|
| `selectedSportIdProvider` | `SelectedSportId` notifier | Active sport slug, e.g. `"football"` |
| `selectedLeagueIdProvider` | `SelectedLeagueId` notifier | Active ESPN league slug, e.g. `"soccer/eng.1"`, or `null` for all |
| `selectedDateProvider` | `SelectedDate` notifier | Date shown in Results tab |

Changing `selectedSportIdProvider` automatically resets `selectedLeagueIdProvider` to `null` (inside `setSportId`).

### Feature notifiers

| Provider | State | Lifecycle |
|---|---|---|
| `liveMatchesProvider` | `LiveMatchesState` | Auto-polls every **12 s** via `Timer.periodic` |
| `resultsProvider` | `ResultsState` | Fetches on build; refreshes on `refresh()` |
| `matchDetailProvider(args)` | `MatchDetailState` | Polls commentary every **6 s** (live) or **30 s** (idle) via a `_pollLoop` |
| `matchCommentaryProvider(matchId)` | `AsyncValue<List<Commentary>>` | Fetched and merged incrementally |
| `sportsProvider` | `SportsState` | Fetches sports + leagues on build |

## APIs

### ESPN (scores + commentary)

Base pattern: `https://site.api.espn.com/apis/site/v2/sports/{sport}/{league}/scoreboard`

- **Live / current**: no query params → returns today's matches
- **Date-specific**: `?dates=YYYYMMDD` → returns matches for that UTC day
- **Commentary**: `https://site.api.espn.com/apis/site/v2/sports/{sport}/{league}/summary?event={matchId}`

`espnLiveEndpointsBySport` in `ApiConstants` lists all active endpoints per sport. `leagueNameToEspnEndpointSlug` maps display league names (e.g. `"Premier League"`) to their ESPN path segment (e.g. `"soccer/eng.1"`).

### TheSportsDB (metadata)

Base URL: `https://www.thesportsdb.com/api/v1/json/3`

Used only for sports list (`/all_sports.php`) and league metadata (`/all_leagues.php`, `/search_all_leagues.php`). Score data is always fetched from ESPN.

Static fallback lists in `SportsRemoteDataSourceImpl` guarantee that the major leagues always appear even when the API is unavailable.

## League Filtering

Selecting a league chip in `LeagueFilterBar` sets `selectedLeagueIdProvider` to the ESPN endpoint slug (e.g. `"soccer/esp.1"`).

When a league is selected, `MatchesRemoteDataSourceImpl` uses a **league-specific ESPN endpoint** instead of the multi-league default endpoints. Because the endpoint already scopes to one league, the name-based `leagueId` filter is dropped from `_applyFilters` to avoid a mismatch between the ESPN response league name (e.g. `"La Liga"`) and the URL slug stored in the filter.

```
league selected → leagueEndpoints != null
  → fetch only from that league's ESPN URL with ?dates=YYYYMMDD
  → effectiveFilters drops leagueId (only keeps sport + date window)
  → _applyFilters matches purely on date + sport
```

## Notifications

Notifications are **score-change driven**, not time-scheduled.

On every live-matches poll (`LiveMatches._fetchMatches`):
1. A snapshot of `{matchId: (homeScore, awayScore)}` is taken from the current state.
2. After the new fetch resolves, each match is checked:
   - If the user follows it (`matchNotificationPreferencesProvider`) and it is live:
     - **New match** (not in previous snapshot) → fires "Live now: …" notification
     - **Score changed** → fires "Score update: …" notification
3. `LocalNotificationService.showInstantNotification` is called (immediate, not scheduled).

`MatchNotificationPreferences` (a Riverpod `Notifier`) stores followed match IDs in a Hive box so the user's follows survive app restarts.

## Error Handling

`RepositoryImpl` classes catch all exceptions in a `_guard` helper and map them to typed `Failure` subclasses:

| Failure | Cause |
|---|---|
| `NetworkFailure` | No internet connectivity |
| `TimeoutFailure` | Connection / receive / send timeout |
| `ServerFailure` | HTTP error with optional status code and message |
| `UnknownFailure` | Any other exception |

The UI reacts to `errorMessage` on the state: if data already exists it shows an inline banner; if the list is empty it shows the full-screen `AsyncStateView.error` widget with a retry button.

## Polling Architecture

`LiveMatches` uses a `Timer.periodic` that restarts on every `build()` call (i.e. when the selected sport or league changes). The timer is cancelled via `ref.onDispose`.

`MatchDetail` uses a recursive `_pollLoop` coroutine instead of a timer. The interval adapts: 6 s when the match is live, 30 s otherwise. A `_pollVersion` counter ensures that stale poll loops from old builds exit cleanly.

Both patterns use a `_buildVersion` / `_pollVersion` integer to guard against race conditions: if the provider rebuilds while a fetch is in flight, the old fetch's result is discarded.

## Generated Files

Files ending in `.freezed.dart` and `.g.dart` are auto-generated by `build_runner` and must not be edited manually. They are committed to the repo because regeneration requires the full toolchain.
